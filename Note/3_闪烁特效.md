# 闪烁特效

闪烁技能首先需要实现角色的溶解与显现。本阶段使用灰度噪声和 Step 构建裁切遮罩，再通过两次 Step 的差提取溶解亮边，最后修正亮边的渐变方向及随溶解进度产生的亮度偏移，实现外侧亮、向角色内部逐渐变暗的过渡。接着分别尝试 WorldAlignedTexture 世界平铺和第二套 UV，改善溶解纹理排布，并记录第二套 UV 在 3ds Max 中的整理方式。完成模型回导与溶解参数端点优化后，开始制作自定义 Niagara 骨骼网格采样模块，从角色表面生成粒子，并兼容发射器的世界空间与本地空间设置。

## 1. 角色溶解的材质设置

本次针对角色原本不透明的表面制作溶解，不复用项目中已有的 `/Game/Effect/Common/MaterialFunction/EF_MF_Dissolve`，而是直接使用阈值比较生成二值遮罩。

这里的“不透明材质溶解”描述的是角色表面的效果需求。实际节点截图中，材质的 **Blend Mode 为 Masked**，通过 **Opacity Mask（不透明蒙版）**决定像素保留或裁切。纯 Opaque 模式不能直接通过这一输入裁切像素。[Opacity Mask 官方说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/material-inputs-in-unreal-engine#opacitymask)

截图中的预览材质使用 `Surface / Masked / Unlit`，便于单独观察遮罩和自发光。接回角色材质时，保留角色所需的基础颜色、法线等表面属性，并合入溶解遮罩与亮边自发光。

后文统一使用以下符号：

| 参数或符号 | 含义 |
| --- | --- |
| `N` | 噪声纹理的灰度值，前文截图取 Texture Sample 的 R 通道；第 8 节使用世界投射结果的 R 通道，第 9 节改用第二套 UV 采样噪声的 R 通道 |
| `D` | 原始 `Dissolve` 参数，约定 1 为不溶解、0 为溶解结束 |
| `T = 1 - D` | 送入 Step 比较的溶解阈值 |
| `W` | `DissolveEdgeWidth`，两次比较之间的阈值差，控制亮边宽度 |
| `C` | `DissolveEdgeColor`，亮边颜色 |

`W` 控制的是噪声灰度区间的宽度，实际显示的空间宽度还取决于纹理局部的灰度变化速度。

## 2. 使用 Step 实现溶解核心

### 2.1 If 与 Step 的比较

最初用 If 将噪声灰度与溶解阈值比较：噪声大于或等于阈值时输出 1，小于阈值时输出 0。输出接入 Opacity Mask，就能让噪声中较暗的区域先消失。

```text
Texture Sample.R → If.A
溶解阈值          → If.B
1                 → If 的 A > B 与 A == B
0                 → If 的 A < B
If 输出           → Opacity Mask
```

![使用 If 比较噪声与溶解阈值](Images/BlinkEffects/01_If_Dissolve.png)

本次只需要 0 和 1 两种结果，因此用 Step 替换 If。UE 材质编辑器中的 Step 将 **X 与 Y 比较：X 小于 Y 时输出 0，否则输出 1**。连接时，噪声接 X，阈值接 Y。[Step 官方说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/math-material-expressions-in-unreal-engine#step)

```text
Texture Sample.R → Step.X
溶解阈值          → Step.Y
Step 输出         → Opacity Mask
```

两种方式都能完成这里的二值溶解。If 可以为不同比较结果指定具体输出值；本次不需要这项灵活性，选择 Step 即可。

截图中的平台统计如下，均为 `High` 质量的 `Pixel Shader / Stationary surface`：

| 平台 | If 版本指令数 | Step 版本指令数 | 变化 |
| --- | ---: | ---: | --- |
| DirectX SM5 | 108 | 108 | 相同 |
| DirectX Mobile | 15 | 11 | 减少 4 条，约 26.7% |

这个示例中 Step 在 Mobile 上的编译指令更少。性能收益应以目标平台的编译和运行结果为准，不能把这组指令差当成所有材质中的固定差值。

![Step 替换 If 后的效果及平台指令统计](Images/BlinkEffects/02_Step_InstructionComparison.png)

### 2.2 用 OneMinus 统一参数方向

直接增大 Step 的阈值，会让更多像素被裁掉。为了符合操作习惯，将对外的 `Dissolve` 参数先做一次 `1-x`：

```text
T = 1 - D
Dissolve → OneMinus → Step.Y
```

这样 `D` 从 1 减小到 0 时，阈值 `T` 从 0 增大到 1，溶解逐渐加深；反向调整则逐渐显现。后续两条 Step 分支都使用这一反相后的阈值。

![Dissolve 参数经过 OneMinus 后再参与比较](Images/BlinkEffects/04_OneMinus_Dissolve.png)

## 3. 两次 Step 相减提取亮边

溶解核心只有保留和裁切两种结果。要得到边缘带，再建立一条阈值降低 `W` 的 Step 分支：阈值较低的分支溶解较少，保留范围更大；阈值较高的分支溶解较多，保留范围更小。

用大范围减去小范围，剩下的就是两条边界之间的区域。

```text
DissolveMin = Step 节点（X = N，Y = T - W）  // 溶解少，保留范围大
DissolveMax = Step 节点（X = N，Y = T）      // 溶解多，保留范围小
EdgeMask    = DissolveMin - DissolveMax
```

这里的 `DissolveMin` 和 `DissolveMax` 沿用截图中的命名，表示两种溶解程度，不是数学 Min、Max 节点。相减顺序必须是 **溶解少的结果减去溶解多的结果**。

按上述比较关系推导，亮边对应的灰度区间为：

```text
T - W ≤ N < T
```

初步将 `EdgeMask × C` 接入 Emissive Color，便能得到一圈纯色亮边。截图早期直接用 Dissolve 作为阈值，加入 OneMinus 后，提取亮边的原理保持一致。

![两次 Step 相减并乘亮边颜色](Images/BlinkEffects/03_StepDifference_Edge.png)

**最终截图将 DissolveMin 接入 Opacity Mask。** 因此实际保留的表面包括亮边带，以及亮边内侧未溶解的区域。如果在这套区间定义下改接 DissolveMax，亮边所在的区域就会被裁掉。

此时亮边内部几乎是统一亮度，带状区域的边界很硬，还没有“最外侧最亮、向内逐渐变暗”的层次。

![纯色亮边的局部效果](Images/BlinkEffects/05_HardEdge_Closeup.png)

## 4. 利用噪声灰度制作边缘渐变

### 4.1 将噪声与亮边相乘

噪声纹理本身包含连续灰度，而 EdgeMask 只负责选出边缘区域。先预览两者的乘积：

```text
初步渐变 = N × EdgeMask
```

这会保留亮边区域内原有的灰度信息，使纯色带出现亮暗变化。

![噪声灰度与亮边遮罩相乘的预览](Images/BlinkEffects/06_NoiseMultiply_Grayscale.png)

但直接使用 `N`，渐变方向与目标相反：靠近已溶解区域的外侧偏暗，靠角色内部的一侧反而更亮。

原因是暗处先溶解。在亮边区间 `T-W ≤ N < T` 中，外侧的噪声值更小，向内的噪声值更大；直接乘噪声就会得到“外暗内亮”。

![直接乘噪声后出现外暗内亮的渐变](Images/BlinkEffects/07_ReversedGradient.png)

### 4.2 反相噪声改变渐变方向

给噪声灰度再加一个 OneMinus：

```text
反相噪声 Q = 1 - N
初步亮边   = Q × EdgeMask
```

外侧较小的噪声值被反相为较大的亮度值，内侧则相反，渐变方向就变为外亮内暗。

这里有两次不同用途的 `1-x`：**`1-D` 用于统一溶解参数方向，`1-N` 用于反转边缘亮度方向。**

![给噪声增加 OneMinus 修正亮暗方向](Images/BlinkEffects/08_OneMinus_Noise.png)

虽然方向正确了，但反相噪声的亮度仍随着溶解进度整体变化。溶解初期边缘偏亮，灰度层次不明显；溶解后期边缘整体变暗，渐变才更容易看出来。

## 5. 使用 Lerp 检查亮度随进度的变化

用颜色代替灰度观察数值分布，可以更直观地判断问题。调试时让较暗的值显示红色、较亮的值显示蓝色：

```text
Lerp.A     = 红色
Lerp.B     = 蓝色
Lerp.Alpha = 1 - N
```

再用边缘遮罩限制显示区域。Alpha 越接近 0 越偏红，越接近 1 越偏蓝。[Lerp 官方说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/math-material-expressions-in-unreal-engine#linearinterpolate)

![使用红蓝 Lerp 检查边缘灰度的节点连接](Images/BlinkEffects/09_Lerp_DebugGraph.png)

调节 Dissolve 后可以观察到：

| 阶段 | 截图参数 | 调试颜色 | 对应现象 |
| --- | --- | --- | --- |
| 溶解初期 | `D = 0.95` | 偏蓝 | 反相噪声数值整体较高 |
| 溶解后期 | `D = 0.25` | 偏红、偏紫红 | 反相噪声数值整体降低 |

![Dissolve 为 0.95 时亮边偏蓝](Images/BlinkEffects/10_Lerp_Dissolve095.png)

![Dissolve 为 0.25 时亮边偏红或紫红](Images/BlinkEffects/11_Lerp_Dissolve025.png)

这说明随着阈值移动，亮边取到的是噪声中不同的灰度区间。纹理没有随时间改变，但当前被选中的边缘灰度发生了整体偏移，并不是只有溶解后期才存在灰度信息。

## 6. 减去原始 Dissolve 抵消亮度偏移

为了让边缘渐变在不同溶解进度下保持一致，从反相噪声中减去**未经 OneMinus 的原始 Dissolve 参数**：

```text
G = (1 - N) - D
  = T - N
```

这个计算将绝对噪声灰度转换为相对于当前阈值的差值。按亮边区间推导，`G` 的范围为：

```text
外侧边界：N = T - W  → G = W，亮度最高
向内过渡：N 逐渐增大 → G 逐渐减小
内侧边界：N 接近 T   → G 接近 0，逐渐变暗
```

只要 `W` 固定，完整亮边区间中的 `G` 就保持在 `0～W`，不再随 `D` 整体偏亮或偏暗。这里减去的是 `D`，如果误接反相后的 `T`，就无法得到上述相对梯度。

例如保持 `W = 0.2`，取亮边上相同的三个相对位置：

| 原始 D | 阈值 T | 外侧 N 与 G | 中间 N 与 G | 接近内侧 N 与 G |
| --- | --- | --- | --- | --- |
| 0.65 | 0.35 | `N=0.15，G=0.20` | `N=0.25，G=0.10` | `N=0.34，G=0.01` |
| 0.25 | 0.75 | `N=0.55，G=0.20` | `N=0.65，G=0.10` | `N=0.74，G=0.01` |

两种进度下的渐变结果一致。接着将 `G` 乘以亮边颜色，形成截图中的 `DissolveColorGradient`：

```text
DissolveColorGradient = G × DissolveEdgeColor
```

![减去原始 Dissolve 后的边缘渐变及最终效果](Images/BlinkEffects/12_CompensatedGradient.png)

## 7. 最终节点整理与输出

### 7.1 按截图保留的连接

最终节点分为两组：一组提取溶解边缘，另一组计算颜色渐变。截图中的 `DissolveEdge` 在 Step 差值之外，还保留了前面测试时的反相噪声乘法。

```text
N = Texture Sample.R
D = Dissolve
W = DissolveEdgeWidth
T = 1 - D

DissolveMin = Step 节点（X = N，Y = T - W）
DissolveMax = Step 节点（X = N，Y = T）
EdgeMask    = DissolveMin - DissolveMax

DissolveEdge          = EdgeMask × (1 - N)
DissolveColorGradient = ((1 - N) - D) × DissolveEdgeColor

Emissive Color = DissolveColorGradient × DissolveEdge
Opacity Mask   = DissolveMin
```

![最终自发光与不透明蒙版输出](Images/BlinkEffects/13_FinalOutput.png)

上述连接复现截图效果。**保持范围稳定的是补偿后的梯度 `G`；额外乘上的 `1-N` 仍会影响最终发光强度。** 如果目标是让同一边缘相对位置的发光值也不随进度改变，可以仅使用二值 EdgeMask 限定渐变：

```text
Emissive Color = EdgeMask × G × DissolveEdgeColor
```

这属于在截图连接基础上的进一步整理。若还希望边缘宽度改变时峰值亮度保持独立，可将 `G` 除以大于零的 `W` 后限制到 0～1，再单独乘发光强度；截图本身没有进行这一步归一化。

### 7.2 参数端点与检查要点

`D=1` 不溶解、`D=0` 完全消失是对外参数的目标约定。按截图最终的 `Opacity Mask = DissolveMin`，当 `D=0` 时阈值实际为 `1-W`，仍可能保留噪声高值区域及尾部亮边。需要严格完全消失时，应额外处理终点遮罩，或重新映射阈值使其越过噪声最大值；重新映射后，渐变应统一使用实际阈值计算 `G=T-N`。第 14 节记录了本次使用 RemapValueRange 优化参数端点的做法。

制作完成后重点检查以下连接：

- 噪声接 Step.X，比较阈值接 Step.Y；较暗的区域应先溶解。
- `DissolveMin - DissolveMax` 的顺序正确，亮边由保留范围较大的结果减去较小的结果。
- 最终 Opacity Mask 接 DissolveMin，确保亮边带处于可见区域。
- 渐变补偿使用 `(1-N)-D`，其中 D 是原始参数；红蓝 Lerp 只用于调试。
- 对比溶解初期、中期、后期的边缘层次，并单独确认完全显现和完全消失两个端点。

## 8. 使用 WorldAlignedTexture 改善 UV 接缝

### 8.1 模型 UV 对溶解纹理的影响

将溶解材质应用到角色后，直接按模型 UV 采样噪声，纹理排布会受到 UV 展开的影响。不同 UV 岛之间的采样位置不连续，可能让溶解图案在拼接处突然断开；局部 UV 的拉伸或缩放也可能让噪声疏密不一致。

下图中，角色背部中间连接处的溶解纹理有明显的拼接感，左右图案衔接不够自然。即使前面的溶解遮罩和亮边计算正确，这类采样问题仍会影响整体观感。

![按模型 UV 采样时，角色背部连接处的溶解纹理不连续](./Images/BlinkEffects/14_UV_Seam_Before.png)

### 8.2 用世界平铺替换原来的噪声采样

使用 **WorldAlignedTexture**，将噪声按世界空间坐标投射到角色表面。它不依赖模型的 UV 展开，并可将 X、Y、Z 方向的投射结果混合，减轻 UV 接缝处的图案断裂，使纹理排布和方向过渡更柔和。[WorldAlignedTexture 官方说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/texturing-material-functions-in-unreal-engine#worldalignedtexture)

截图中的连接如下：

```text
溶解噪声 Texture Object → WorldAlignedTexture.TextureObject
常量 65                → WorldAlignedTexture.TextureSize
WorldAlignedTexture 的 XYZ Texture 输出 → 后续溶解计算
```

![Texture Object 接入 WorldAlignedTexture，并设置 TextureSize 为 65](./Images/BlinkEffects/15_WorldAlignedTexture_Graph.png)

| 节点或引脚 | 本次设置与作用 |
| --- | --- |
| `Texture Object` | 使用原来的溶解噪声纹理，为函数提供纹理对象；不能直接用 Texture Sample 的 RGB 采样值替代这一输入 |
| `TextureSize (V3)` | 控制纹理沿世界 X、Y、Z 轴的平铺尺寸，单位为世界单位；截图输入标量 `65`，会扩展为 `(65, 65, 65)` |
| `XYZ Texture` | 使用三个方向混合后的投射结果，覆盖角色不同朝向的表面 |

`TextureSize` 越大，同一块噪声图案覆盖的世界空间范围越大，溶解块越大、排布越疏；数值越小则越细密。这里的 `65` 是本次效果使用的尺寸，可按角色大小和期望的溶解块尺寸调整。

为沿用前文统一的标量灰度 `N`，可在 `XYZ Texture` 输出后通过 **ComponentMask（仅勾选 R）**取出 R 通道，替换原来的 `Texture Sample.R`：

```text
N = WorldAlignedTexture.XYZ Texture 的 R 通道

N → 两个 Step 的 X 输入
N → 亮边分支中的 OneMinus（1 - N）
N → 渐变补偿计算 G = (1 - N) - D
```

替换时，遮罩与亮边各分支应使用同一份世界投射噪声，避免裁切边界和发光边缘错位。前面的 Dissolve 参数方向、两次 Step 相减以及渐变补偿公式均保持不变。

### 8.3 替换后的效果

改用世界投射后，背部原先沿 UV 拼接处断开的图案明显缓和，溶解纹理在角色表面的分布更连贯，没有原先直接的接缝感。

![世界平铺后的角色溶解效果，背部纹理衔接更加自然](./Images/BlinkEffects/16_WorldAlignedTexture_Result.png)

世界投射改善的是噪声的空间排布，不会改变模型 UV 本身。默认投射固定在世界空间，角色移动或骨骼动画时，表面可能相对纹理产生滑动；应用到闪烁技能时，还需在实际动作中检查这一表现。[世界空间纹理的运动特性](https://dev.epicgames.com/documentation/en-us/unreal-engine/texturing-material-functions-in-unreal-engine#worldalignedtexture)

## 9. 使用第二套 UV 采样溶解纹理

### 9.1 在 UE 材质中切换 UV 通道

除了世界对齐投射，还可以为溶解纹理指定模型的**第二套 UV**。这套 UV 可以单独为特效整理，不必沿用角色基础贴图的 UV 排布。本次使用第二套 UV 后，溶解纹理的分布效果也比较自然。

在材质中添加 **TextureCoordinate（TexCoord）** 节点，将 **Coordinate Index（坐标索引）设为 1**，再接入溶解噪声 Texture Sample 的 UVs 输入。UE 的 UV 索引从 0 开始，因此 `TexCoord[1]` 表示第二套 UV。[TextureCoordinate 官方说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/coordinates-material-expressions-in-unreal-engine#texturecoordinate)

```text
TexCoord（Coordinate Index = 1）→ 溶解噪声 Texture Sample.UVs
Texture Sample.R              → N → 原有溶解遮罩与亮边计算
```

![TexCoord 坐标索引设为 1，接入溶解噪声的 UVs 输入](./Images/BlinkEffects/17_SecondUV_TexCoord.png)

这里替换的是噪声采样所使用的坐标。前面的 Step 比较、亮边提取和渐变补偿仍然使用同一份灰度 `N`，无需更改公式。模型导入 UE 时需要保留第二套 UV，角色基础颜色等贴图继续使用各自原有的 UV 设置。

![使用第二套 UV 采样后的角色溶解效果](./Images/BlinkEffects/18_SecondUV_Dissolve_Result.png)

### 9.2 在 3ds Max 中查看两套 UV

回到 **3ds Max**，在 **Unwrap UVW（UVW 展开）**修改器的“通道”区域查看“贴图通道”，并打开 UV 编辑器。对于本模型的这两套 UV，通道对应关系如下：

| 用途 | 3ds Max 贴图通道 | UE 的 Coordinate Index |
| --- | ---: | ---: |
| 第一套 UV | 1 | 0 |
| 第二套 UV | 2 | 1 |

先选择**贴图通道 1**。下图是模型的第一套 UV，可以看到大量拆分、打包后的 UV 岛。

![3ds Max 贴图通道 1，查看模型原有的第一套 UV](./Images/BlinkEffects/19_Max_UV_Channel1.png)

将**贴图通道切换为 2**，即可查看已经制作好的第二套 UV。这一步是在查看已有通道，并不代表只修改通道编号就能自动生成图中的排布。

### 9.4 使用相对输入精确偏移一个 UV 单位

UE 材质采样中通常按 **U 对应 X、V 对应 Y** 理解纹理坐标：在常见的贴图显示约定下，U 从左向右由 0 到 1，V 从上向下由 0 到 1。这描述的是一张纹理的基础区间，**UV 本身可以小于 0 或大于 1**。3ds Max 的 UV 编辑器中，V 的显示方向与 UE 的上述贴图约定不同，不能直接把两者的屏幕方向混用。

如果希望精确平移一整格，可以使用 UV 编辑器左下角的数值输入：

1. 选中需要整体偏移的全部 UV。若要移动整个通道，可全选；若只移动主体或附属元素，则只选对应部分。截图中选中的是角色主体，下方飘带等部分未选中。
2. 将左下角 **Absolute/Relative Type Ins（绝对/相对输入）**切换到**相对输入**模式。
3. 保持 U、W 不变，在 **V 输入框中输入 `-1`** 并确认。
4. 所选 UV 会在当前 Max 视图中向下移动一个完整的 UV 单位，即一张基础 UV 方格的高度。

相对模式表示在当前坐标上增加偏移量。本次操作可写为 `V新 = V原 - 1`，并不是把所有选中 UV 的 V 坐标直接设为 `-1`。[3ds Max 绝对/相对输入说明](https://help.autodesk.com/cloudhelp/2022/ENU/3DSMax-Modifiers/files/GUID-C65A1B09-3670-4E7E-BCFC-13E10C831817.htm)

![选择角色主体 UV，并定位左下角的相对输入与 V 数值栏](./Images/BlinkEffects/24_Max_Relative_Offset.png)

![输入 V 偏移量 -1 后，所选主体 UV 整体向下移动一格](./Images/BlinkEffects/25_Max_V_Minus1_Result.png)

这一操作用于精确整理 UV 的位置。若纹理使用 Wrap 重复寻址，且材质直接使用未缩放的 UV 采样，整数格平移会采到相同的重复图案；它本身不会自动产生新的溶解顺序。最终噪声排布仍取决于整套 UV 的展开、缩放与材质中的采样设置。[UE 中超出 0～1 的 UV 与重复采样说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-uv-channels-with-static-meshes-in-unreal-engine)

### 10.4 导入后模型发黑的排查方法

**后续文件检查已确认：导出的 FBX 中，10 个材质的漫反射颜色均为黑色，详见 10.5。** 这是模型发黑的直接材质原因，Max 中应用修复后的实际表现仍待视口验证。截图中模型轮廓仍可见，仅凭黑色表面无法判定网格或 UV 损坏。UE 中的完整材质节点效果也不能假定会通过 FBX 在 Max 中原样重建；导入后的基础颜色、贴图连接或子材质可能需要另行处理。

为了先看清表面并继续制作 UV，可以在用于 UV 编辑的场景副本中，给角色网格临时指定一个简单灰色材质：

1. 选中**角色网格对象**。如果角色由多个网格组成，应选择全部需要处理的网格；避免把周围的骨骼或辅助对象当作网格选中。
2. 按 **M** 打开材质编辑器，新建一个 **Physical Material（物理材质）**。
3. 将 **Base Color（基础颜色）设为中灰色**，金属度设为 `0`，粗糙度可设为 `0.5`；不连接贴图，保持不透明、不透射。
4. 选中这个材质，点击 **Assign Material to Selection（将材质指定给选定对象）**。
5. 如果模型恢复为正常的灰色明暗，说明原导入材质需要检查，可先用该临时材质继续观察和编辑 UV。[Autodesk 材质创建与指定示例](https://help.autodesk.com/cloudhelp/2021/ENU/3DSMax-Tutorial/files/GUID-88BFA730-0BD3-4543-ADA9-C745A9D95A6C.htm)

如果指定灰色材质后仍然全黑，再打开视口左上角的着色菜单，进入 **Lighting and Shadows（照明和阴影）**，选择 **Illuminate with Default Lights（使用默认灯光照明）**；也可在 **Active Viewport Settings（活动视口设置）**的照明选项中选择 **Default Lights**。不同 Max 版本的菜单位置可能略有差异。[Autodesk 视口照明设置](https://help.autodesk.com/cloudhelp/2026/ENU/3DSMax-Basics/files/GUID-E7FB1028-2566-4B32-801A-30079978ECDF.htm)

如果简单材质与默认灯光下仍有局部黑面、缺面，或从不同角度观察时表面消失，再检查面朝向与法线。当前截图不足以认定法线翻转，不宜直接对整个模型执行 Flip。

### 10.7 为什么之前导出的 Nyx 没有整体发黑

用户确认之前导出的文件是 `Nyx_Skeletal_C.FBX`。对比该文件与原始 `Muriel_GDC.FBX` 的实际数据，可得到以下结果：

| 检查项 | Nyx_Skeletal_C.FBX | Muriel_GDC.FBX |
| --- | --- | --- |

| 连接到 `DiffuseColor` 的贴图数量 | 5 | 0 |

![Nyx 与 Muriel 的实际 FBX 导出数据对比报告截图](./Images/BlinkEffects/32_Nyx_Muriel_Export_Comparison.png)

Nyx 的 7 个非黑色材质保留了 `(0.8, 0.8, 0.8)` 的漫反射值，而且部分材质保留了颜色贴图连接。Muriel 的所有材质都是黑色，唯一保留的贴图连接是面部的 `NormalMap`，不能提供基础颜色。这解释了为什么两者导入后的表面显示可能不同；Nyx 中仍有 10 个黑色漫反射材质，也不能把它看作完整恢复了 UE 原材质。

同时修正前面排查结论的权重：Nyx 的主体材质也存在 `Opacity = 1` 与 `TransparencyFactor = 1` 的组合，因此透明字段不一致并不是 Muriel 独有的现象，不能单独用于解释这次与之前的显示差异。

### 11.2 添加 UVW 贴图，并确认修改器顺序

先关闭 UV 编辑器，再添加一个 **UVW 贴图（UVW Map）**修改器。**本流程中，UVW 贴图必须位于 UVW 展开之下**，让投影生成的坐标先进入展开编辑阶段。截图中的堆栈从上到下为：

## 14. 重映射溶解参数，让蓝图曲线使用 0～1

### 14.1 溶解值为 0 时仍有碎边的原因

接下来优化溶解参数的端点行为，继续保持对外约定：**`Dissolve = 1` 为未溶解，`Dissolve = 0` 为溶解结束**。

前面的最终遮罩使用 `DissolveMin`，它为亮边保留了宽度为 `W` 的灰度区间。因此，原始参数直接降到 0 时，遮罩的比较阈值仍然是 `1-W`，噪声高值区域中的细碎亮边可能还没有完全消失。

此前可以让角色蓝图中的曲线继续降到负数，以推动这些区域消失，但这样会让蓝图端的“完全溶解值”依赖材质内部的亮边宽度。现在将这部分补偿放到材质中处理，使蓝图继续使用 0～1 的参数范围。

### 14.2 使用 RemapValueRange 调整材质内部的参数

截图使用 `MPC_Nyx` 中的 **Dissolve** 和 **Edge** 参数，将原始 Dissolve 接入 **RemapValueRange**，同时计算 `Dissolve - Edge`，接到目标下限。

![Dissolve 接入 RemapValueRange，Dissolve 减 Edge 后接入 Target Low](./Images/BlinkEffects/50_Dissolve_RemapValueRange.png)

这里继续用 `D` 表示蓝图传入的原始 Dissolve，用 `W` 表示亮边宽度（本图参数名为 `Edge`），新增 `R` 表示重映射结果。按 0～1 的输入设计，连接和范围应确认为：

| RemapValueRange 引脚 | 设置或连接 |
| --- | --- |
| Input | 原始 `Dissolve`，即 `D` |
| Input Low | `0` |
| Input High | `1` |
| Target Low | `Subtract.A = D`、`Subtract.B = W` 的结果，即 `D-W` |
| Target High | `1` |
| Result | `R`，接入后续溶解计算 |

截图没有展开未连接引脚的内部默认值，复现时需要确认 Input Low、Input High、Target High 与表中一致。Target Low 随 `D` 一起变化，因此这套连接的整体响应并不是固定上下限的线性映射。

按上述范围，重映射结果为：

```text
R = (1-D) × (D-W) + D × 1

D = 1 → R = 1
D = 0 → R = -W
```

也就是说，蓝图端的参数仍然降到 **0**，材质内部已经将它转换到 **`-W`**，额外推进了一个边缘宽度。原先需要在曲线里手动输入的负值，现在由材质根据 Edge 自动补偿。

### 14.3 与溶解遮罩和亮边渐变保持一致

如果沿用前面的 OneMinus 与两次 Step，接入重映射后，实际阈值应统一改为：

```text
D = 蓝图传入的原始 Dissolve
R = RemapValueRange 的 Result
T = 1 - R

DissolveMin = Step 节点（X = N，Y = T-W）
DissolveMax = Step 节点（X = N，Y = T）
EdgeMask    = DissolveMin - DissolveMax
G           = T-N = (1-N)-R

Opacity Mask = DissolveMin
```

这里的渐变补偿使用 **`R`**。第 6 节尚未引入重映射时使用 `(1-N)-D`；引入重映射后，改为 `(1-N)-R`，才能与当前裁切阈值保持一致。蓝图和 MPC 仍然保存原始 `D`，材质后续分支使用 `R` 及其对应阈值。

当 `D=0` 时，`R=-W`，因此 `T-W=1`，原先因亮边宽度而提前保留的高值区间被推进到噪声上限。这就是本次清除尾部碎边的原理。由于 Step 在相等时仍输出 1，若噪声中恰好存在值为 1 的像素且仍有残留，可增加少量终点余量，或额外在 `D=0` 时关闭最终遮罩与亮边输出。

重映射后的 `R` 需要能够低于 0；在接入后续计算前将它 Clamp／Saturate 到 0～1，会截掉这部分补偿。

### 14.4 将角色蓝图的曲线终点改回 0

回到角色蓝图的 **Timeline_DodgeEffect**，调整其中的 Dissolve 浮点曲线：溶解阶段从 **1 降到 0**，在 0 保持一段时间，再从 **0 回到 1**，完成角色显现。具体时长按技能节奏设置。

![Timeline_DodgeEffect 中的 Dissolve 曲线，最低值使用 0，随后回到 1](./Images/BlinkEffects/51_Dissolve_Timeline_ZeroEndpoint.png)

现在无需为了清除剩余亮边，把曲线最低点设为负数。蓝图只负责控制“未溶解 → 完全溶解 → 显现”的进度，边缘宽度对应的数值补偿由材质内部完成。调整后分别检查 `D=1` 的完整显示、`D=0` 的完全消失，以及中间阶段的亮边渐变是否正常。

## 15. 创建自定义骨骼网格粒子位置模块

### 15.1 创建 Module 并设置使用范围

接下来为角色闪烁添加从角色表面发射的粒子。一般可以直接使用 UE 自带的 **Skeletal Mesh Location** 模块；本次还需要为后续的第二套 UV 区域筛选等功能保留扩展位置，因此自行创建 Niagara Module，先完成随机取点与粒子位置写入。

这里所说的“从骨骼发射”，具体是**在骨骼网格体经过蒙皮变形后的三角面上取点**，而不是只在骨骼关节或 Socket 上生成粒子。

模块命名为 **`NM_SkeletalMeshLocation`**。在脚本设置中，模块使用位掩码保留 `Module`，并勾选 **Particle Spawn Script** 和 **Particle Update Script**，允许模块用于粒子生成或更新阶段。截图中 `Particle Event Script` 的蓝色背景是菜单当前高亮项，不代表已勾选。

![设置模块使用位掩码，勾选 Module、Particle Spawn Script 与 Particle Update Script](./Images/BlinkEffects/52_SkeletalMeshModule_Usage.png)

继续设置模块的分类与可见性：

| 设置 | 本次取值 | 用途 |
| --- | --- | --- |
| Category（类别） | `A_Effect` | 在模块列表中归入自定义特效分类 |
| Library Visibility（库可见性） | `Exposed` | 便于在添加模块时搜索到该脚本 |

![模块分类设为 A_Effect，库可见性设为 Exposed](./Images/BlinkEffects/53_SkeletalMeshModule_Settings.png)

使用位掩码决定模块**允许放在哪些阶段**，并不会让它自动在两个阶段都执行。本阶段用于初始化发射位置时，放在 **Particle Spawn** 中，并置于 Initialize Particle 等可能初始化位置的模块之后，避免刚采样的位置被覆盖。

### 15.2 添加 Skeletal Mesh Reader 输入并获取世界位置

在模块的 **Map Get** 中添加一个模块输入，名称为 **Skeletal Mesh Reader**，类型选择同名的骨骼网格数据接口类型。这个输入负责提供需要采样的骨骼网格数据；将模块加入实际发射器后，还需要让该 Reader 指向目标角色的 Skeletal Mesh Component，才能采到角色当前姿态下的位置。

从该输入调用 **Get Skinned Triangle Data WS**。其中 `WS` 表示 World Space，输出的 `Position` 是三角面上指定采样点经过蒙皮变形后的**世界空间位置**。节点还会输出 Velocity、Normal、Binormal、Tangent，本阶段先只使用 Position。

模块的参数映射主线保持为：

```text
InputMap → Map Set.Source
Map Set.Dest → Output Module.OutputMap

InputMap → Map Get.Source
Map Get.Skeletal Mesh Reader → Get Skinned Triangle Data WS.SkeletalMesh
```

在 **Map Set** 中添加 **`Particles.Position`**（截图显示为“粒子 Position”）。先将采样得到的 Position 接入该属性，即可完成世界空间发射器的基础位置写入；第 15.4 节再补上本地空间分支。正式属性名为 `Particles.Position`。

### 15.3 使用 Random Tri Coord 生成三角面采样坐标

`Get Skinned Triangle Data WS` 除了 SkeletalMesh，还需要输入 **Coord**，用于确定“取哪个三角面，以及取这个面上的哪个位置”。

添加 **Random Tri Coord**，将同一个 Skeletal Mesh Reader 接入它的 `SkeletalMesh`，再将输出 `Coord` 接到 Get Skinned Triangle Data WS 的 `Coord` 输入。三角面坐标包含**三角面索引和面内重心坐标**，并不是一个普通的 XYZ 位置。[Mesh Tri Coordinate 官方结构说明](https://dev.epicgames.com/documentation/unreal-engine/API/Plugins/Niagara/FMeshTriCoordinate)

截图使用以下随机输入链路：

```text
Calculate Random Range Integer.RandomValue
    → int32 -> Niagara Rand Info
    → Random Tri Coord.RandomInfo

Map Get.Skeletal Mesh Reader → Random Tri Coord.SkeletalMesh
Random Tri Coord.Coord      → Get Skinned Triangle Data WS.Coord
Get Skinned Triangle Data WS.Position → Map Set.Particles.Position（暂按世界空间连接）
```

其中整数随机节点在截图中的设置为：

| 参数 | 截图取值 |
| --- | --- |
| Integer Min | `0` |
| Integer Max | `999999` |
| Seed | `-1` |
| Evaluation Type | `Spawn Only` |
| Fixed Random Seed | 不勾选 |
| Override Seed | 不勾选 |
| Randomness Mode | `Simulation Defaults` |

![随机整数转为 Niagara Rand Info，经 Random Tri Coord 取样后写入粒子位置](./Images/BlinkEffects/54_SkeletalMeshModule_RandomTriCoord.png)

**注意区分随机信息的范围与三角面索引范围。** 按截图接线，整数先转换为 `Niagara Rand Info`，接入的是 `RandomInfo`，不是三角面索引引脚。因此这里的 `999999` 是该随机输入的示例上限，不能据此认定模型有一百万个三角面，也不需要把它解释为骨骼网格的最大三角面数。实际的随机三角面坐标由 Random Tri Coord 根据 Reader 的采样数据生成。

如果后续改为**手动生成三角面索引**，才需要按实际采样 LOD 的三角面数量 `N` 限定有效索引为 **`0～N-1`**，并另外提供合法的面内重心坐标；存在采样区域筛选时，还要区分筛选列表索引与原始三角面索引，不能直接混用。当前图不需要改成这套手动索引流程。

### 15.4 使用静态开关适配发射器的坐标空间

采样节点输出的是世界空间位置，而 **`Particles.Position` 应使用发射器的模拟空间**：Local Space 关闭时为世界空间，开启时为本地空间。UE 官方将 Simulation Space 定义为由发射器 Local Space 设置决定的空间。[Niagara 空间说明](https://dev.epicgames.com/documentation/unreal-engine/niagara-scratch-pad-modules-in-unreal-engine?lang=en-US#transformationspace&positionoffset)

因此，在采样位置与 Map Set 之间添加 **Static Switch（静态开关）**，使用发射器的编译常量自动选择分支：

| Static Switch 设置 | 本次取值 |
| --- | --- |
| Static Switch Type（静态开关类型） | `Bool Constant`（布尔常量） |
| Compiler Constant（编译器常量） | `Emitter.LocalSpace` |

接着添加 **Transform Position**，将采样得到的世界位置接入它，并设置：

| Transform Position 设置 | 本次取值 |
| --- | --- |
| Source Space | `World` |
| Destination Space | `Local` |
| Apply Scale | 勾选 |

最后连接静态开关的两个分支：

```text
P_WS = Get Skinned Triangle Data WS.Position
P_Local = Transform Position（P_WS，World → Local，Apply Scale = true）

Static Switch（Emitter.LocalSpace）
    If True  ← P_Local
    If False ← P_WS

Static Switch 输出 → Map Set.Particles.Position
```

![以 Emitter.LocalSpace 为静态开关条件，本地空间分支执行 World 到 Local 的位置转换并勾选 Apply Scale](./Images/BlinkEffects/55_SkeletalMeshModule_LocalSpaceSwitch.png)

**Local Space 为 True 时使用转换后的位置，为 False 时直接使用世界位置。** 这样同一个模块就能用于两类发射器，切换发射器设置时无需手工改线。这里的 Local 是 Niagara 组件／系统的本地空间，不是任意一根骨骼的局部空间。

Apply Scale 勾选后，空间转换会包含缩放，使世界位置转换回本地坐标时与组件变换匹配。若把世界坐标直接写入本地空间发射器，后续显示时会再套用组件变换，容易出现整体偏移；反过来，世界空间发射器也不能直接使用已转换的本地坐标。

### 15.5 当前效果与后续扩展

编译并保存模块后，在闪烁特效的粒子生成阶段使用它，配置目标角色的 Skeletal Mesh Reader。当前完成的是**从角色蒙皮表面随机采样粒子出生位置**。截图中，角色表面及周围已经出现白色粒子点，与原有紫色、金色特效叠加。

![角色闪烁特效的阶段效果，骨骼网格表面及周围出现白色粒子点](./Images/BlinkEffects/56_SkeletalMeshModule_ParticleResult.png)

本节基础图尚未使用第二套 UV 筛选，单靠 Random Tri Coord 不会自动排除脸部、翅膀等下移 UV 的区域。第 16 节继续使用**同一个 Coord**读取第二套 UV（索引 `1`），按实际 UV 区域剔除粒子，使位置采样与 UV 筛选对应到同一处表面。

若后续需要粒子持续贴随骨骼动画，应保存出生时的 Coord，并在 Particle Update 中用该坐标重新读取蒙皮位置；不要每帧重新随机取点，否则粒子可能在角色表面跳动。只在 Particle Spawn 写入位置时，粒子出生后不会自动跟随骨骼形变；开启 Local Space 只会让其随 Niagara 组件的整体变换运动。

检查本阶段效果时，分别切换 Local Space 开关，并移动、旋转及缩放 Niagara 组件，确认两种设置下粒子的出生位置都能落在角色表面；再播放角色动画，区分“出生位置正确”和“持续贴随蒙皮”这两种需求。

## 16. 读取第二套 UV，剔除飘带和盔甲区域的粒子

### 16.1 用采样点的 UV 生成筛选标记

当前随机取点覆盖骨骼网格表面，飘带、盔甲等不需要生成粒子的部位也会出现粒子。前面已经将这些部件的第二套 UV 从主体区域移开，现在读取这份区域标记，在 Niagara 中剔除对应粒子。

回到 `NM_SkeletalMeshLocation`，添加 **Get Tri UV**，使用与位置采样**相同的 Reader 和 Coord**，并将 **UV Set 设为 `1`**，读取第二套 UV。输出接 **Break Vector 2D**，其中 X 为 U，Y 为 V；这里只比较 Y。

```text
Skeletal Mesh Reader → Get Tri UV.SkeletalMesh
Random Tri Coord.Coord → Get Tri UV.Coord
Get Tri UV（UV Set = 1）.UV → Break Vector 2D → Y（V）
V → 比较节点 → Select → Map Set.Particles.Kill
```

在 Map Set 中新增 **`Particles.Kill`**，类型为 **Float**。这里它是自定义的数值标记，写入它本身不会直接删除粒子，还需要下一步的 Kill Particles 模块执行删除。

![读取第二套 UV 的 V 分量，通过比较和 Select 写入 Particles.Kill](./Images/BlinkEffects/57_UV2_GetTriUV_KillMask.png)

### 16.2 区分文字中的 V 小于 0 与截图中的实际判断

按“排除区域位于 `V<0`”的约定，可以把该区域标记为待删除。但**本次截图实际使用的是 `V < 1.0`，Select 为 True 输出 `1`，为 False 输出 `0`**。下一张截图中的 Kill Particles 则删除 `Kill == 0` 的粒子。因此，按截图复现时，完整逻辑是：

```text
KeepRegion = V < 1.0
Particles.Kill = KeepRegion ? 1.0 : 0.0
删除条件 = Particles.Kill == 0.0

结果：保留 V < 1 的点，剔除 V ≥ 1 的点。
```

这个属性虽然叫 Kill，截图中的 **1 实际表示保留、0 表示删除**。不要仅凭参数名把 Select 的输出反接。

如果 Niagara 中实际读到的排除区域确实是 `V<0`，并且仍保留 `Kill == 0` 的删除条件，则应改为：

```text
Particles.Kill = (V < 0.0) ? 0.0 : 1.0
```

两套判断对应不同的 UV 区域约定，不能直接混用。Max 中的“下移”不能代替对 UE 实际读数的核对；导入过程中 V 方向的转换可能改变区外坐标落在数轴的哪一侧。本次按截图记录 `V<1` 的保留逻辑，复现时分别检查主体与飘带上的 UV 值，再确定阈值及比较方向。筛选使用原始 UV，不先做 Frac、Wrap 或 Clamp。

### 16.3 在 Particle Update 中执行 Kill Particles

回到 Niagara System，在 **Particle Update** 中添加 **Kill Particles**，使用 **Set Bool by Float Comparison** 设置删除条件：

| 参数 | 本次设置 |
| --- | --- |
| A | `Particles.Kill` |
| B | `0.0` |
| Comparison Type | `A Equal To B` |

![Kill Particles 使用浮点比较，删除 Particles.Kill 等于 0 的粒子](./Images/BlinkEffects/58_KillParticles_FloatComparison.png)

生成阶段先采样位置并写入筛选标记，更新阶段再执行删除。这样不需要修改实际模型几何，就能排除被 UV 标记的飘带、盔甲等部位；它减少的是保留下来的粒子，不会减少角色模型的面数。

![剔除后的粒子人形轮廓，移除被 UV 标记区域的粒子](./Images/BlinkEffects/59_UV2_FilteredParticleBody.png)

## 17. 为模块增加第二套位置 PositionB

### 17.1 用静态开关选择写入的粒子属性

接下来准备第二套骨骼采样位置，让粒子能够从第一套角色位置向第二套角色位置移动，为后续角色粒子化与重组建立基础。

在模块中新增 **Static Switch**，命名为 **`PositionB`**，使用可由模块实例设置的布尔静态开关。在开关的输出添加 **Niagara Parameter Map（Niagara 参数映射）** 类型，使它切换两条 Map Set 的结果。它与第 15.4 节读取 `Emitter.LocalSpace` 的编译常量开关作用不同。

![为 PositionB 静态开关添加 Niagara Parameter Map 类型的输出](./Images/BlinkEffects/60_PositionB_StaticSwitch_Map.png)

保留原 Map Set，再增加一个新的 Map Set，新增 **`Particles.PositionB`**，类型选择 **Position**，与 `Particles.Position` 一致。将经过 Local Space 分支处理的位置同时接到两条分支对应的位置属性：

| PositionB 开关 | 选择的 Map Set | 写入位置 |
| --- | --- | --- |
| False，不勾选 | 原 Map Set | `Particles.Position` |
| True，勾选 | 新 Map Set | `Particles.PositionB` |

两个 Map Set 的 Source 都接同一份输入参数映射，各自的 Dest 接静态开关的对应输入，开关输出再接 Output Module。它们是**并列分支**，不是先后串接；PositionB 分支保留已有的粒子位置，只写入目标位置属性。

```text
输入参数映射 ┬→ Map Set（Position、Kill）  → If False
             └→ Map Set（PositionB、Kill） → If True
                                          ↓
                             Static Switch（PositionB）→ Output Module
```

![两条 Map Set 分别写入 Position 和 PositionB，由静态开关选择输出](./Images/BlinkEffects/61_PositionB_MapSetBranches.png)

截图中两个分支也都写入了 `Particles.Kill`。因此第二套骨骼采样不仅计算目标位置，还可能覆盖当前筛选标记；第 17.3 节需要按这个实际行为安排顺序。

在**编辑输入层级（Edit Input Hierarchy）**中，将 PositionB 拖到 Skeletal Mesh Reader 上方，放在最上层，方便在模块实例中先选择用途，再指定采样源。

![在输入层级中将 PositionB 排在 Skeletal Mesh Reader 上方](./Images/BlinkEffects/62_PositionB_InputHierarchy.png)

### 17.2 在 NS 中创建两套骨骼网格用户参数

在 Niagara System 的用户参数面板新增两个参数：

| 用户参数名称 | 类型 | 用途 |
| --- | --- | --- |
| `Skeletal Mesh 01` | Niagara Data Interface Skeletal Mesh | 第一套骨骼网格采样源 |
| `Skeletal Mesh 02` | Niagara Data Interface Skeletal Mesh | 第二套骨骼网格采样源 |

这里使用的是 **Skeletal Mesh 数据接口**，在模块中作为 Skeletal Mesh Reader 输入；不是 Skeletal Mesh Renderer 渲染器类型。还需要为两个数据接口分别配置实际采样的骨骼网格组件，用户参数名称本身不会建立组件绑定。

![NS 中新增 Skeletal Mesh 01 和 Skeletal Mesh 02 两个骨骼网格数据接口用户参数](./Images/BlinkEffects/63_NS_TwoSkeletalMeshUserParameters.png)

在 **Particle Spawn** 中，原有 `NM Skeletal Mesh Location` 的 PositionB **不勾选**，Reader 绑定 **User.Skeletal Mesh 01**，负责写入粒子的起始位置及筛选标记。

![生成阶段使用第一套骨骼，PositionB 不勾选](./Images/BlinkEffects/64_Spawn_SourceMesh01.png)

在 **Particle Update** 中，再添加一次同一个模块。截图中的实例显示为 `NM Skeletal Mesh Location 001`，这是第二次使用该模块；将 PositionB **勾选**，Reader 绑定 **User.Skeletal Mesh 02**，持续更新目标位置 `Particles.PositionB`。

![更新阶段使用第二套骨骼，PositionB 勾选，模块排在 Kill Particles 之后](./Images/BlinkEffects/65_Update_TargetMesh02_AfterKill.png)

两套采样位置均经过同一个发射器空间转换逻辑，后续才能直接插值。若两套源是同一模型的两个组件，要让粒子对应到相同表面位置，应使用一致的采样 Coord、拓扑与采样 LOD；仅设置相同随机范围并不能保证两个模块实例随机到同一个三角面。当前截图没有展示显式保存并复用 Coord 的接线，稳定对应关系仍需在模块中确认。

### 17.3 更新阶段先剔除，再采样 PositionB

按本次接线，关键执行顺序为：

```text
Particle Spawn
    Initialize Particle
    NM Skeletal Mesh Location（PositionB = false，Skeletal Mesh 01）

Particle Update
    Particle State
    Kill Particles
    NM Skeletal Mesh Location 001（PositionB = true，Skeletal Mesh 02）
    设置 Particles.Position（下一节的 Lerp）
```

**第二套位置模块放在 Kill Particles 之后。** 因为它也会写入 Kill，如果放在 Kill Particles 前面，第一套骨骼产生的筛选标记会先被第二套结果覆盖，删除模块就可能无法按原来的飘带区域剔除粒子。

这个顺序确保先消费已有的筛选标记；但 B 分支写入的 Kill 仍会留给下一帧。如果第二套骨骼的 UV 布局或采样点与第一套不同，还需明确筛选依据：若只按第一套骨骼决定出生资格，可进一步让 B 分支只写 PositionB，保留第一套的标记。截图当前保留两个分支都写 Kill 的结构。

## 18. 使用 Lerp 过渡位置，并挂载到 Dodge 动画

### 18.1 在更新阶段重新设置粒子位置

在第二套位置采样模块之后，添加 **设置（粒子）Position**，为 `Particles.Position` 选择动态输入 **Lerp Position**：

| 输入 | 本次连接 |
| --- | --- |
| A | `Particles.Position` |
| B | `Particles.PositionB` |
| Alpha | `Float from Curve` |
| Float from Curve.CurveIndex | `Particles.NormalizedAge` |
| Scale Curve | `1.0` |

![Lerp Position 在当前位置和 PositionB 之间插值，Alpha 使用粒子归一化年龄采样曲线](./Images/BlinkEffects/66_LerpPosition_NormalizedAgeCurve.png)

基本插值关系为：

```text
P_new = (1 - Alpha) × P_current + Alpha × PositionB
```

Alpha 为 0 时保持当前位置，为 1 时到达第二套位置。截图中曲线从约 `(0, 0)` 上升到 **`(1, 0.25)`**，这里先保留这个调试设置，观察粒子逐渐向第二套骨骼聚拢。

需要注意，A 使用的是**每帧执行到这里时的当前位置**，上一帧插值结果已经写回该属性。因此这是逐帧趋近目标，曲线终值 0.25 不代表粒子整个生命周期只移动总路程的四分之一。若要用统一进度直接控制两端位置，应另外保存起点 PositionA，再计算 `Lerp(PositionA, PositionB, Progress)`；若起点也要随动画变化，则每帧更新该起点属性。

截图中后面仍有 Drag、Solve Forces and Velocity。它们可能继续改变本帧最终位置；当前可以保留观察效果，若要求严格贴合插值结果，则应检查后续位移模块，并将最终位置写入安排在合适的位置。

## 19. 使用第二套 UV 控制头部先归位、脚部后归位

### 19.1 将 V 分量转换为归位权重

现在继续调整粒子重组的节奏，希望**头部的粒子率先归位，脚部的粒子随后归位**。前面制作的第二套 UV 按角色从头顶到脚底排列，因此可以直接利用 V 分量，为不同高度的采样点生成不同的归位权重，不必另外按骨骼名称划分区域。

回到 `NM_SkeletalMeshLocation`，沿用 Get Tri UV（UV Set = `1`）与 Break Vector 2D，从 **Y 输出读取 V**。按头部 V 较小、脚部 V 较大的布局，先使用 **OneMinus（1-A）**反相，得到头部较大、脚部较小的数值：

```text
原始 V → OneMinus → 1 - V
```

这里依据的是第二套 UV 的高度排布，不是实时世界空间高度；角色弯腰、翻滚时，权重仍对应模型表面的原有部位。若实际读到的 V 方向相反，应先核对头脚数值，再调整反相关系，使头部权重大于脚部。

### 19.2 将权重下限限制为 0.3，并写出 UVMask

直接使用 `1-V` 时，靠近脚底的权重可能接近 0。后续用它调节归位速度，会出现部分粒子移动过慢、迟迟无法聚拢的情况。因此在 OneMinus 后添加 **Clamp**：

| Clamp 输入 | 本次设置 |
| --- | --- |
| A | `1-V` |
| Min | `0.3` |
| Max | `1.0` |

在 Map Set 中新增 Float 类型的 **`Particles.UVMask`**，将处理后的权重写入，供 NS 后续的位置插值读取。这里“暴露 V”是把由 V 计算出的数值写成粒子属性，并不是新增一个需要手工填写的模块输入。

```text
Get Tri UV（UV Set = 1）.UV
    → Break Vector 2D.Y
    → OneMinus（1-V）
    → Clamp（Min = 0.3，Max = 1.0）
    → Map Set.Particles.UVMask

UVMask = Clamp(1-V, 0.3, 1.0)
```

![第二套 UV 的 V 经反相生成 UVMask，并准备添加最小值为 0.3 的 Clamp](./Images/BlinkEffects/70_UVMask_OneMinus_Clamp.png)

**截图中，UVMask 仍直接连接 OneMinus 的输出，Clamp 的 Result 尚未接出。** 完成限制时，需要将 UVMask 原来的连线替换为 **Clamp.Result → UVMask**；只放置 Clamp 而不使用它的输出，最小值限制不会生效。截图展示的是 PositionB 分支的 Map Set，应确保它在后续 Lerp 读取 UVMask 之前执行。

以主体 V 从头部约 0 增加到脚底约 1 为例，处理结果为：

| 示例部位 | V | 1-V | Clamp 后的 UVMask |
| --- | ---: | ---: | ---: |
| 头部 | 0.0 | 1.0 | 1.0 |
| 身体中部 | 0.5 | 0.5 | 0.5 |
| 脚底 | 1.0 | 0.0 | 0.3 |

这些数值用于说明权重变化，具体部位的 V 以实际展开为准。Clamp 是截断范围，不是把整个 0～1 线性重映射到 0.3～1；当 V 大于等于 0.7 时，这些点的权重都会被限制为 0.3。

原有 Kill 分支继续使用**未经反相和 Clamp 的原始 V**进行区域判断。UVMask 控制归位权重，Kill 控制是否剔除粒子，两者分别从原始 V 分流，避免速度限制改变区域筛选结果。

### 19.3 将 UVMask 用于位置过渡

将 UVMask 写出后，还需要在 NS 中参与位置计算，才能产生头脚归位速度的差异。本次截图没有展示 NS 中最终的 Alpha 接线；若沿用第 18.1 节的逐帧 Lerp，可以按下面的方式接入：

```text
BaseAlpha = Float from Curve（Particles.NormalizedAge）
Alpha = Clamp(BaseAlpha × Particles.UVMask, 0.0, 1.0)
Particles.Position = Lerp(Particles.Position, Particles.PositionB, Alpha)
```

这是在前一节连接基础上补充的接法：同一 BaseAlpha 下，头部权重较大，每帧向目标位置靠近得更多；脚部权重较小，聚拢更慢，从而形成头部先归位、脚部随后归位的层次。0.3 限制的是 **UVMask 的下限**，不是最终 Alpha 的下限；当 BaseAlpha 为 0 时，粒子仍保持不动。

这套接法产生的是不同部位的**趋近速度差异**。由于 Lerp 的 A 仍是当前位置，不能把它理解为头部和脚部各自在指定时刻精确完成的进度；若后续需要严格同步完成时刻，应继续使用独立起点与分区进度控制。

![利用角色上下 UV 权重调整粒子归位层次的阶段演示](./Images/BlinkEffects/71_UVMask_HeadFirstReassembly.gif)

播放 Dodge 动作时，观察头部是否先形成轮廓、脚部是否随后收拢，并检查低权重粒子能否在预期生命周期内完成聚拢。若脚部仍明显拖尾，可以配合提高基础曲线的归位强度或调整粒子寿命；当前先以 UVMask 最小值 `0.3` 作为调试起点。

## 20. 扩展采样模式：三角面、顶点、骨骼或插槽

### 20.1 为瞬移条带准备关节位置

接下来制作角色瞬移时的条带，希望拖尾从脚部、膝盖、手部、头部等关节位置生成。前面的模块只在三角面上取点，现在为同一个模块增加**顶点采样**和**骨骼／插槽采样**，让身体粒子与关节条带共用位置模块。

新建枚举资源 **`EM_SkeletalMeshLocation`**，添加以下枚举项：

| 枚举项 | 显示描述 | 采样位置 |
| --- | --- | --- |
| `Triangles` | 三角面 | 三角面内部的随机点 |
| `Vertices` | 顶点 | 蒙皮后的模型顶点 |
| `BoneOrSocket` | 骨骼或者插槽 | 指定的骨骼或插槽位置 |

![采样模式枚举，包含 Triangles、Vertices、BoneOrSocket](./Images/BlinkEffects/72_SamplingMode_Enum.png)

### 20.2 用枚举静态开关选择位置数据

在 `NM_SkeletalMeshLocation` 中新增静态开关 **`StaticSamplingMode`**，将开关类型设为枚举，并选择刚创建的枚举资源。开关的三路输入统一使用 Position 类型，分别连接对应的数据接口函数。

```text
Triangles：
    Random Tri Coord.Coord → Get Skinned Triangle Data WS.Coord
    Get Skinned Triangle Data WS.Position → If Triangles

Vertices：
    Random Vertex.Vertex → Get Skinned Vertex Data WS.Vertex
    Get Skinned Vertex Data WS.Position → If Vertices

BoneOrSocket：
    Module.Socket Or Bone Index → Get Filtered Socket or Bone.Socket Or Bone Index
    Get Filtered Socket or Bone.Bone → Get Skinned Bone Data WS.Bone
    Get Skinned Bone Data WS.Position → If BoneOrSocket
```

各节点的 SkeletalMesh 输入都使用当前模块的 **Skeletal Mesh Reader**。新增的 **Socket Or Bone Index** 为 Integer 类型，表示过滤列表中的索引；先通过 Get Filtered Socket or Bone 映射，再读取骨骼变形后的世界位置，不把它直接当成整个 Skeleton 的原始骨骼编号。

![三种数据采样路径进入枚举静态开关，再统一处理发射器坐标空间](./Images/BlinkEffects/73_SamplingMode_ThreePositionPaths.png)

三路输出都是世界空间位置，因此选出结果后，再统一接入第 15.4 节的 **World → Local 转换与 Emitter.LocalSpace 开关**，最后按 PositionB 开关选择写入 `Particles.Position` 或 `Particles.PositionB`。

顶点模式与三角面模式的区别在于：前者只能落在现有顶点上，分布受模型顶点密度影响；后者可以落在面内。骨骼／插槽模式则适合精确指定关节，不能将三种模式理解为同一种随机取点方式。

**UV 筛选也需要与采样模式对应。** 三角面继续使用同一个 Coord 读取 Get Tri UV；顶点应按同一个 Vertex 读取顶点 UV。骨骼／插槽本身没有唯一对应的表面 UV，不应再用无关的随机三角面 UV 决定它的 Kill 或 UVMask。关节引导粒子可以跳过表面 UV 剔除，并为 UVMask 明确设置默认值或另设关节权重，避免复制模块后关节点被随机删除。

### 20.3 整理模块参数顺序

在编辑输入层级中按下面的顺序排列：

1. `PositionB`：决定写入起始位置还是目标位置。
2. `Skeletal Mesh Reader`：指定采样源。
3. `StaticSamplingMode`：选择三角面、顶点或骨骼／插槽。
4. `Socket Or Bone Index`：指定骨骼／插槽过滤列表中的索引。

![模块输入层级，将采样模式与骨骼索引排在 Reader 之后](./Images/BlinkEffects/74_SamplingMode_InputHierarchy.png)

## 21. 用 16 个关节引导粒子生成 Ribbon

### 21.1 复制发射器并设置过滤骨骼

回到 `NS_Dodge_Nyx`，复制现有发射器，作为条带的运动源，最终命名为 **`NE_TrailHead`**。将模拟目标改为 **CPU**，用 **Spawn Burst Instantaneous 一次生成 16 个粒子**。本次关节数量较少，且后续使用 Niagara 位置事件链，两端都采用 CPU 模拟。[官方事件机制说明](https://dev.epicgames.com/documentation/unreal-engine/events-and-event-handlers-in-niagara-effects-for-unreal-engine?lang=en-US)

将采样模式设为 **BoneOrSocket**，在 Skeletal Mesh Reader 中配置 **Filtered Bones（过滤的骨骼）**，共 16 项。初始截图以头部开头，包含脊柱、左右上臂、前臂、手、大腿、小腿与脚等部位；过滤插槽列表为空，所以本次实际使用的是骨骼。

![CPU 发射器中设置 16 项过滤骨骼，初始列表以头部开始](./Images/BlinkEffects/75_TrailHead_FilteredBones_HeadFirst.png)

在模块的 **Socket Or Bone Index** 输入中，绑定动态输入 **Return Exec Index**：

```text
一次生成 16 个粒子 → 执行索引 0～15
Return Exec Index → Socket Or Bone Index
过滤列表第 i 项 → 第 i 个引导粒子的骨骼位置
```

![Socket Or Bone Index 绑定 Return Exec Index](./Images/BlinkEffects/76_BoneIndex_ReturnExecIndex.png)

这样在这批生成粒子中，实现的是**16 个粒子分别对应 16 项过滤骨骼**，而不是沿角色表面等距离分布。列表数量与发射数量应一致；数量改变时，要同步处理索引范围。两套 Reader 都用于同一组关节过渡时，其过滤列表也应保持对应关系。

Return Exec Index 是当前执行顺序，不是永久身份。若在更新阶段也直接用它查询骨骼，部分粒子死亡后数据压缩可能改变对应关系。需要稳定跟随同一个关节时，应在生成阶段保存骨骼列表索引为粒子属性，更新阶段复用该索引，不能依靠固定 ID 自动锁住 Exec Index。

![关节引导粒子分布在头部、手臂、身体和腿脚等位置](./Images/BlinkEffects/77_TrailHead_JointParticlePreview.png)

### 21.2 发送位置事件，并启用持久 ID

在 `NE_TrailHead` 的 **Particle Update** 末尾添加 **Generate Location Event**，放在位置插值与 Solve Forces and Velocity 等位置更新之后，使事件发送本帧最终的引导粒子位置。

| 参数 | 本次设置 |
| --- | --- |
| Event Type | `Every Frame` |
| Event Generation Enabled | 勾选 |
| Use Event Probability | 不勾选 |
| Delay Before Sending Events | 不启用 |

![NE_TrailHead 每帧发送位置事件，NE_Ribbon 接收事件生成拖尾点](./Images/BlinkEffects/78_TrailHead_GenerateLocationEvent.png)

在发射器属性中开启 **Requires Persistent IDs（需要持久 ID）**，尤其是事件来源 `NE_TrailHead`；接收端也按事件链配置要求检查。这里的“固定 ID”指持久粒子身份，用于区分不同来源，与固定 Lifetime、骨骼列表顺序是不同设置。官方事件说明要求事件发射器启用该选项。

### 21.3 添加 Ribbon 发射器及事件接收

新增 **`NE_Ribbon`**，使用 CPU 模拟与 **Ribbon Renderer**。添加 Event Handler，将 Source 指向 **`NE_TrailHead` 的 `LocationEvent`**，再在事件组中添加 **Receive Location Event**。

| --- | --- |
| Source | `NE_TrailHead / LocationEvent` |
| Execution Mode | `Spawned Particles` |
| Max Events Per Frame | `0`，不额外限制消费数量 |
| Spawn Number | `1`，每个事件生成一个拖尾点 |
| Random Spawn Number | 不勾选 |

![Ribbon 事件处理器绑定 NE_TrailHead 的 LocationEvent，单个事件生成一个粒子](./Images/BlinkEffects/79_Ribbon_EventHandler.png)

截图中 Ribbon 的 **Spawn Per Unit 仍处于启用状态**。如果目标是只由这 16 个关节事件生成拖尾，应关闭这类额外的常规生成模块，避免混入没有正确来源的点；若保留，需明确它们如何获得位置和分组。现有飞行特效笔记第 6 节使用了同样的位置事件链，可对照其接收属性配置。

## 22. 调整条带收尾、纹理密度与汇聚方向

### 22.1 排查生命周期差异造成的末尾拉伸

本次观察到条带收尾时出现较长的跨接，有些轨迹呈现流光掠过身体的感觉。调试时发现粒子寿命使用随机范围，截图为 **Lifetime Mode = Random，Min = `0.8`，Max = `1.3`**，不同粒子不会在同一时刻结束。

![随机生命周期范围为 0.8～1.3，粒子结束时刻存在差异](./Images/BlinkEffects/81_Ribbon_RandomLifetime.png)

本次可以先将 Lifetime Mode 改为 **Direct Set／固定值**，统一同批引导粒子的寿命，并为 Ribbon 使用确定的寿命，使收尾更可控。若希望两者使用相同的寿命长度，可以设为同一个固定值；具体数值按 Dodge 时长调整，截图没有给出最终固定值。

需要区分：**寿命不一致不等于拖尾必然接到另一个粒子。** 接到哪些点，还由 Ribbon ID 分组、组内连接顺序以及骨骼索引是否稳定决定。出现跨关节长线时，除了寿命，也应检查是否共用默认 Ribbon ID、更新阶段的 Exec Index 是否因死亡而变化，以及是否混入常规生成的点。固定寿命可以减少本次错峰死亡引起的变化，但不能代替这些检查。

引导粒子在开始时出生，Ribbon 点则在后续每帧出生，因此**相同的寿命长度也不表示它们同时死亡**。若要求严格统一结束时刻，应按来源结束时刻计算 Ribbon 的剩余寿命，或另行控制淡出与系统停用；若需要自然留尾，则允许历史 Ribbon 点在源停止发送后逐渐消失。

当前也可以按审美需求保留适量的流光收尾。本次觉得这种尾端扫过身体的表现可以接受，重点是确认它在重复播放中可控，而不是把所有拉伸都一律消除。

### 22.2 缩短平铺长度，让拖尾纹理更密集

为了让条带上的纹理更密集，在 **Ribbon Renderer → UV0 Settings** 中使用按距离平铺的 UV 模式。截图为 **Tiled By Distance（By Particles.RibbonUVDistance）**，**Tiling Length（平铺长度）为 `-300.0`**。

![Ribbon Renderer 的 UV0 按距离平铺，截图中的平铺长度为 -300](./Images/BlinkEffects/82_Ribbon_UV0_TilingLength.png)

这次修改的是**条带渲染器的 UV 平铺长度**，不是材质中的同名参数。Tiling Length 表示平铺对应的世界单位长度；在相同条带长度和 UV 缩放下，减小平铺长度的绝对值，纹理重复得更密，增大则更疏。[官方 UV 平铺长度说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Plugins/Niagara/FNiagaraRibbonUVSettings)

`-300` 记录本次截图取值。负号还可能影响 UV 沿带方向，不能把“改为负数”当成增加密度的原因；复现时应在当前 UE 版本与材质上确认方向和重复效果，并避免将长度设为 0。还要确保事件接收链提供了该模式使用的 Ribbon UV Distance。

![调整条带表现后，流光与角色原有紫金特效叠加](./Images/BlinkEffects/83_JointRibbon_TunedResult.png)

### 22.3 调整过滤骨骼顺序，改变本次收尾的汇聚趋势

继续观察本次条带，可以看到末尾有向头部拉伸、汇聚的趋势。初始过滤列表把头部放在前面，结合当前索引分配、粒子结束及条带连接方式，会影响可见的连接方向。为了让这种收尾更偏向脚部，将**脚部放到过滤列表前面、头部放到最后**。

**列表顺序不会单独产生朝脚部的力，也不会自动反转第 19 节的 UVMask。** 这里记录的是当前接线下通过重排索引改变收尾观感的调试方法；如果每个关节已经使用独立且稳定的 Ribbon ID 与骨骼索引，单纯重排列表通常只会改变编号对应，不应让原本独立的拖尾跨接。需要稳定、可设计的向下汇聚时，应明确设置目标位置、关节权重或连接顺序，再保留需要的流光效果。
